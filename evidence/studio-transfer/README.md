# Independent creation and upstream correction — 2026-11-12

`two-avatars/` is the original unaided result. A fresh creator received only the repo skill, current
studio contract/commands and this new intent: a friendly science-community cover with two distinct,
stylistically consistent cartoon avatars, clean negative space and no text. It could not read source,
existing images or a reference, and could not edit JSON/SVG to bypass an operation gap.

The creator actually inspected important normal/alignment images and completed seven supported
parameter/placement edits through the public CLI. Its `REVIEW.md` records actual commands, bindings,
limits and completed check output. It independently composed two head instances, rather than just
running the author's demo. This is limited reuse of one head recipe, not unaided invention of
anatomy, expression, pose, clothing or a science-specific illustration.

Two fresh image-only reviewers (`avatars_review_a/b`) saw only its check images. Both noted rigid
hair/back edges, simplified ears/features, similar faces/expressions and excessive lower whitespace.
One explicitly identified the copper head's blue internal hair lines; the other found the bob fringe
crowding the brows. Flat rendering itself is a style choice within the user-accepted default
direction, but that acceptance does not erase these defects or approve this new complete cover.
No whole-artwork pass or baseline promotion is claimed.

## Corrected operation gaps

The creator also observed that the object intent still claimed a side part after changing to bob,
and found no CLI creation-time canvas-format control. These were retained in the raw result.

The blue line was a real primitive bug: bob-only comb lines used a default blue omitted from the
hair-colour replacement map. A regression covering **all hair marks in both supported styles** failed
on that omission before the fix. After correction it passes, including an actual warm-hair raster
check outside the separate eye material. Purple pupils are intentional eye colour, not hair leakage.

Stock intent now describes purpose without repeating mutable style/colour values. Object selection
exposes an explicit text `intent` control; custom author intent is not silently rewritten. New scenes
accept optional `--size WIDTHxHEIGHT` and `--background`. The cover's unspecified format made a square
interpretation legitimate, so the missing format control did not invalidate the original test.

`two-avatars-engine-fix/` is an **assisted correction**, kept separate from the original transfer.
The same input is rebuilt with coherent copper hair; public intent edits describe the two actual
avatars. It is not presented as a second unaided creation. Its validation confirms changes confined
to the partner's hair, identical unrelated-avatar pixels, 55 passing combined checks and unchanged
default-head PNG bytes relative to the earlier accepted-direction sample. Remaining art criticism
still applies. Correcting a colour operation does not create new character expressions or facial
identity controls; that is the next concrete capability gap.
