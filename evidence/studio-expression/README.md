# Expression, attention and an actual cover — 2026-11-12

This advance follows a real independent-creation limit: the two avatars differed mostly by palette
and fringe. It adds bounded character intent controls to the already accepted flat-head direction,
without claiming new anatomy, 3D head turns, a complete facial rig or natural emotional acting.

## Observed revisions

The initial `00-before` → `04-attention-left` sequence and `strip/` changed brows/mouth and conjugate
gaze. Two fresh image-only reviewers (`expression_review_a/b`) saw the check images and agreed that
isolated line changes did not coordinate with the eyelids. That version is preserved, not promoted.

`refined/` and `lid-coordinated/` used the existing eye generator with optional upper/lower lid
factors. A first smile raised the lower lid too far: iris/glint remnants became little fragments.
Two new image reviewers (`expression_lids_review_a/b`) independently named that artifact. The
execution-capable `usability/REVIEW.md` found the commands operable and selected parts correct, but
also found gaze weak at normal size because most of the pupil was hidden. Usability did not erase
the visible defect.

`lid-study/` and `curious-study/` are explicitly isolated specification studies, not studio edit
candidates. Their parameter sheets compare actual rendered alternatives without pixel metrics or
reference input. Product files stayed frozen during the independent execution test. `source.py`
copies preserve each study's original temporary script and execution-context assumptions; these
are dated research records, not standalone installation instructions.

The rejected narrow-eye implementation and dependencies are frozen in `source-before-balanced/`.
The final `balanced/` uses a milder lower-lid lift, retaining visible pupil centers and useful gaze,
and a clearer opening under the questioning brow. `usability-balanced/REVIEW.md` independently
confirms improved iris visibility and same-direction gaze without visible escape from the eyelids.
It still reads as a relaxed half-open eye rather than universal emotional expression.

Two fresh balanced-image reviewers (`expression_balanced_review_a/b`) still find thick outer lashes,
mechanical feature grouping and ambiguous expression: the questioning face can read as one-sided
raised brows, and the smile can read as appraising. These are open art limits. One review described
the narrow eye as an upper-lid change; the compiled upper curve is unchanged for smile, so that
causal interpretation was not adopted. Its observation of a compressed/stiff appearance is retained.

An actual locality check also caught a guide defect: sclera-only bounds omitted the moving outer
lash wing. Eye/expression selections now include the actual lash contours. Closeups extending past
the canvas have an opaque neutral workspace, distinguishing document paper from the outside area.
Normal artwork stays clean and unchanged by either diagnostic improvement.

## Reuse in a concrete asset

`community-cover/` is a main-author composition after the independent raw transfer, not a second
unaided transfer. It combines the head recipe, warm sky field, relative placement, small opposing
tilts and gaze in a 960×540 banner. Its compact semantic input is
`examples/studio/community_cover.json`; no generated path was manually edited.

Two image-only reviewers (`community_cover_review_a/b`) retain hard hair/back edges, simplified ears,
unequal-looking eyes and weak small nose/mouth details. A separate purpose-aware reviewer
(`community_cover_usability`), viewing only this asset for the explicit simple flat community-banner
use, finds minimum practical value: clear coherent characters, some variation/attention, stable
placement and usable margins, with no blocker requiring a redraw. It identifies overlap in a few
hair outlines, tight bob/brow spacing and weak interaction as optional improvement limits.
That conditional asset-usability conclusion is separate from blind criticism and human acceptance.
The user has been asked asynchronously whether this specific banner is usable; no answer is assumed.

## Verification and scope

`validation.json` records 60 combined operation/head/expression/scenery/visibility/oracle tests,
81 CPU smoke checks plus wave/strand assertions, exact default-head PNG preservation relative to
the earlier integration, and repeated SVG/CPU-PNG identity for the cover. The reference image is
absent in this worktree. Tests prove feature-local changes, same-direction pupil movement, selected
guide coverage, and pupil-center visibility in this **open-eye smile**. The over-closed prototype is
a negative control for the last property, not a universal rule against intentionally closed eyes.

These are bounded reusable head/background and creation-loop capabilities. The current portrait
gate, broad original illustration and general drawing mastery remain open. No GPU/model workflow,
generated bitmap asset, sealed brief, baseline promotion or original portrait edit was used.
