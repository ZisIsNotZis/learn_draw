## Findings supporting PASS

- The code path is consumed, not import-only: `r1_scene.build_svg` sends each authored `ShapeSpec.controls` through `build_visible_smooth_component`; adapter samples then explicitly validates that exact tuple, uses it as the `Component.outline`, maps through `SupportFrame.local_to_world` and `Camera.project` via `component_faces`, derives fills with `visible_regions`, and boundary spans with `visible_segment_spans`. `emit_study_svg` rejects non-typed/incomplete mappings and identity mismatch; actual SVG fill paths are emitted from returned visible-region paths and outline strokes from returned authored boundary spans. Semantic line marks are independently support/camera projected and clipped via `visible_segment_spans` against sibling faces, then emitted as SVG line paths. Inspected output files contain the expected computed fill/outline/semantic-line paths (A: 11 fills, 237 boundary fragments, 5 semantic lines; B: 27 fills, 629 boundary fragments, 12 semantic lines); path geometry is not replaced by raw input SVG.
- Test assertions instrument guard, face, fill, and span calls and check consumed object/sample identity; reject self-crossing before face generation; compare actual adapter fill regions and boundary spans/length with and without an occluder; reject raw-SVG emitter substitution; and exercise integration on complete A/B scenes. Thus bypass/occlusion tests are substantive, not grep-only.
- Shape contour input is constrained at `controls()` to <=4 literal coordinate pairs; all A contours are four pairs and tests enumerate all A/B `ShapeSpec` adapter inputs. B's torso/limb/head/hand/prop forms are generated in the frozen construction functions from relation/support controls, then reduced to four cardinal/generated points; this is generated outline output, not a hidden long literal contour in `r1_scene.py`. Semantic line marks are authored endpoint pairs, separately allowed by contract. Source review found no manual visibility-cut intervals or traced dense contour.
- A/crop registration is explicitly documented in manifest (same 400x480 viewport, no resize; crop maps to source origin (500,320)); crop and source digests are checked by the preparation script and match manifest. Renderer API is output-directory only; `run_r1.py`/`r1_scene.py`/adapter have no target-image argument/access, and test denies target opens while performing two equal-hash SVG writes.
- B test covers all three study-case validation calls, baseline/variant target changes, control separation >0.1, and torso width change. Head and generated shape bounds, authored semantic line endpoints and labels are tested against their panel viewports. Supports, contact and near-miss are tested within `validate_study_case`'s declared bounded XY-footprint/range model; this is not general 3D collision proof.
