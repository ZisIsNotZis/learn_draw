# Visibility clipping: bbox overlap is only a broad phase

A projected triangle's bounding box is a cheap rejection test, not proof that its interior occludes another triangle. For opaque visibility clipping, first retain the existing bbox broad phase, then require positive-area intersection of the projected convex triangles before building a depth cutter. Edge and point contact must not invoke polygon subtraction; a represented positive overlap must still reach depth comparison.

Why this constraint matters here: the canonical resolver's equal-depth declaration bias sent shared-edge-only neighbors through clipping. Its existing tolerant line clip produced repeated-vertex, zero-area fragments and positive floating-point slivers. Compound-path serialization then changed Chromium's coverage along projected mesh edges. In the fixed fine arch this correlated with 44 base-colour deviations in safe interior samples; an isolated strict SAT precheck restored exact raw-fill coverage while retaining genuine depth fragments.

This is evidence from bounded computed geometry, not a production rule approval or whole-drawing acceptance. Preserve depth-crossing behavior, same-component self-occlusion, and the exact coplanar declaration tie. A prior oblique ring area expectation changes materially under the candidate and is still under review.

The independent coverage gate is separate from the visibility kernel. Classify a sampled point as a fragment-boundary case using Euclidean point-to-segment distance in centered screen coordinates (fixed predeclared tolerance `1e-12`), with explicit segment endpoints and exact zero-length-edge handling. Do not scale raw cross-product tolerance as `max(1, edge_length)`. Separately exclude/count source edges and a source-derived near-policy band `1e-5 + EPS`; measure both false positives and false negatives only outside those masks. Boundary-inclusive membership is diagnostic ambiguity, never a no-loss pass. Candidate V3/canonical remain unchanged during this V4 audit.
